# Independent product visual review signing (v1)

This is an offline reviewer-only workflow. It does not create a key, determine rights, call YouTube, or turn machine QA/ASR into content approval. The producer and publisher only receive the Ed25519 **public** key as `PRODUCT_CONTENT_REVIEW_PUBLIC_KEY`; neither runtime receives the private key, its path, or a signing command.

1. Independently review complete video **and** audio, canonical product and affiliate identity, each exact source image, applicable public promotional-video rights, and similarity against every current publication. Record the reviewer type, actual modalities/methods, unresolved ranges, and evidence. A source URL or Coupang search result is provenance, not a rights grant. The reviewer must reject missing/ambiguous evidence.
2. Prepare a `product-visual-signing-manifest/v1` JSON outside the repository. Its `files` entry binds the current `video`, `audio`, `narration`, `script`, `captions`, and each `sourceImages[]` path to a lowercase SHA-256. Caption JSON must declare `schema: fresh-caption-timeline/v1`, the exact current TTS `audioSha256`, the canonical **display** name, and cues containing that name; an old caption timeline or speech-only alias in the display name fails closed. Each image also needs `productId`, `rightsStatus: "verified"`, `rightsEvidenceId`, `rightsEvidencePath`, and `policyReference`.
3. Set `review.reviewerType` explicitly. For `human`, the dated `fullHumanContent` and `exactSpokenName` attestations must both pass. For `composite`, bind the full `ai-content-assessment/v2` JSON as `review.aiContentAssessment: { path, sha256 }`; it must match current product/video/audio hashes, independently review visual and actual audio (not ASR-only), cover all current prior publications, and have no unresolved required content ranges. `ai_visual` and `ai_audio` alone cannot sign a release receipt. The legacy `ai_multimodal` value remains accepted for existing signed receipts, but new V2 assessments label combined visual/audio review `composite`. The signer never treats AI as human. In both modes, `productIdentity`, `affiliateIdentity`, `rights`, and `crossVideo` attestations must pass. The signed receipt binds `reviewerType`, `contentEvidenceSha256`, caption hash, media hashes, canonical identity, affiliate URL hash and reviewed ledger IDs. An AI content verdict does **not** grant image usage rights; those are independently evidenced.
4. Provision an Ed25519 private key under a separate reviewer OS identity and restricted external path. Do not put it in Git, producer/publisher environment, Vercel, logs, or their readable ACL. A path outside Git alone is **not** proof of OS isolation. Keep the public key separately. Do not sign until an access test proves producer/publisher identities cannot read the private key.
5. From an isolated review workstation, run:

   ```text
   node --import tsx scripts/video-automation/sign-product-visual-review-v1.ts --manifest <external-review-manifest.json> --current-ledger <external-current-publisher-state.json> --private-key-file <external-restricted-reviewer-key.pem> --public-key-file <external-reviewer-public-key.pem> --output <external-new-receipt.json>
   ```

   The CLI never prints key material or affiliate URLs. It refuses a key or output under the Git checkout and will not overwrite an existing receipt. It checks all current file hashes and verifies the signed receipt with the supplied public key before writing.
6. Bind the unchanged receipt to the exact product/job. The existing producer READY and publisher pre-insert gates verify the public signature, product/name/affiliate/video hashes, current publication IDs, and current MP4 bytes. This is not permission to enable a disabled Task or upload.

For the 2026-09-24 historical 7 and fresh 3 diagnostics, exact acoustic spoken-name approval and public-video image rights are incomplete. No operating signing key was provisioned or used. AI visual sampling and ASR do not satisfy the release gates. All remain excluded from release.
