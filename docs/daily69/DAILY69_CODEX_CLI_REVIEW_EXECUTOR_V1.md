# Daily69 Authenticated Codex CLI Review Executor V1

## Decision

Daily69 uses the already authenticated Codex CLI of the same Windows user that runs `Minz-Commerce-VideoBatch-NoUpload-V1`. The integration does not read, copy, export, or embed authentication material. It invokes `codex exec` non-interactively with `--ephemeral`, `--json`, a strict output schema, local image evidence, and a read-only sandbox.

`CODEX_REVIEW_EXECUTOR=AUTHENTICATED_CODEX_CLI` is eligible only after a current-user Scheduled Task diagnostic completes. A diagnostic receipt always has `provenance=diagnostic` and cannot become queue promotion evidence.

## Natural pipeline

1. Generate no-upload video and complete machine QA.
2. Bind `operationNamespace`, `queueId`, `productKey`, `videoPath`, and the executor-computed video SHA-256.
3. Attach at most three local visual artifacts: first frame, first-three-second contact sheet, and full contact sheet.
4. Run one global review at a time.
5. Validate strict structured output and reject any changed queue/product/SHA binding.
6. Materialize an immutable per-video review artifact and an executor receipt.
7. Bind the receipt SHA-256 into `CodexReviewEvidenceV2`.
8. Promote only `reviewResult=pass` with no hard blocker. Model block goes to `manual_review`; executor failure goes to `blocked`.

## Bounds

- operation-wide CLI invocation cap: 69;
- per-video attempt cap: 2;
- global executor concurrency: 1 lock;
- queue batch size: at most 3;
- clearly transient CLI/structured-output failures receive at most one retry;
- completed exact-SHA receipts are deduplicated;
- conflicting queue/product binding for the same SHA fails closed.

## Evidence contracts

The strict model output includes `schemaVersion`, `queueId`, `productKey`, `videoSha256`, `reviewResult`, `hardBlockers`, `safeSummary`, `reviewedAt`, `reviewerType`, and `executorType`, plus three bounded visual notes. The model-provided time is informational; the trusted `reviewedAt` is generated by the executor after the CLI returns.

The executor receipt records only bounded local paths, hashes, result fields, token counts exposed by CLI JSONL, and no-upload counters. `CodexReviewEvidenceV2` additionally requires:

- `executorType=authenticated_codex_cli`;
- `reviewProvenance=natural|carry_forward_revalidation`;
- exact receipt path and SHA-256;
- exact immutable review artifact path and SHA-256;
- exact video path, size, and SHA-256.

Closeout and the independent post-closeout auditor recompute the media, review artifact, and executor-receipt bindings. No diagnostic receipt, legacy boolean review, machine-QA-only state, or changed video SHA can satisfy ready.

## Commands

```text
npm run queue-video:codex-review-diagnostic -- --request <diagnostic-request.json> --output <diagnostic-result.json>
npm run daily69:first-day:review-carry-forward -- --source-root <source> --target-namespace <namespace> --contact-root <contacts> --evidence-root <evidence> --output <registry.json>
npm run daily69:first-day:apply-carry-forward-review -- --queue-root <prepared-operation> --registry <registry.json>
```

All commands preserve `SAFE_TO_UPLOAD=false`, `SAFE_TO_PUBLIC_UPLOAD=false`, and `PLATFORM_UPLOAD=0`.
